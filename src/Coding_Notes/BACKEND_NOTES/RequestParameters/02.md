Great question — and you're absolutely right to notice that the **query parameter** style (`?characterName=Lyn`) is more common in URLs you see on the web.

Let’s break this down:

---

## ✅ Path Variables vs. Query Parameters: When and Why?

### 🔹 **Path Variables** (`/byCharacter/Lyn`)

**Used for:**

* Identifying a specific resource.
* Cleaner, more RESTful when referring to a particular *entity*.

**Example:**

```http
GET /users/123
GET /articles/hello-world
```

### 🔹 **Query Parameters** (`/byCharacter?characterName=Lyn`)

**Used for:**

* Filtering, searching, or tweaking the *behavior* of the request.
* More flexible — you can add optional parameters like `?sort=asc&limit=10`.

**Example:**

```http
GET /search?query=swords&limit=5
GET /products?category=weapons&sort=price
```

---

## 🧭 Why Are Query Parameters More Ubiquitous?

### ✅ 1. **Browser and UX-Friendly**

* Easier to copy, bookmark, and share.
* Works better with form submissions and frontend frameworks.

### ✅ 2. **Supports Multiple Filters**

* Path variables are limited to a specific order and count.
* Query parameters allow for optionality and flexibility:

  ```
  /byCharacter?name=Lyn&equipped=true&slot=mainhand
  ```

### ✅ 3. **Search Engines and APIs**

* Search URLs (`?q=something`) are query-parameter based by default.
* APIs that offer complex filtering or pagination rely on query parameters for readability and ease of use.

---

## 🛠️ So, Which Should You Use?

### Use **path variables** when:

* You're accessing a specific, uniquely identified resource.

  ```http
  /characters/Lyn/equipment
  ```

### Use **query parameters** when:

* You're *filtering* a collection or adjusting the behavior of the response.

  ```http
  /equipment?characterName=Lyn
  ```

---

## 🧩 In Your Case:

If `byCharacter` is essentially a *filter* over the whole equipment collection, then:

```http
GET /equipment?characterName=Lyn
```

...is more semantically correct **and more common** in public-facing APIs.
