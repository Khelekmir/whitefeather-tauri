To shift from manually writing large `INSERT INTO` SQL statements in your script to using CSV files for population, you can take advantage of **PostgreSQL's `COPY` command**. It allows bulk importing of data from a CSV file directly into a table. Here's how you can update your setup to use this method:

---

### ✅ **Step 1: Prepare Your CSV Files**

Create a directory like:

```
backend/src/main/resources/data/
```

And save your CSV files there, for example:

```
armor.csv
amulet.csv
weapon.csv
```

Each CSV file should:

* Have **no header row** (unless you use `HEADER` in the `COPY` command).
* Use standard CSV formatting (e.g., `,`-delimited).
* Match the **column order** of the table.

Example of `armor.csv`:

```csv
'Iron Helm','heavy','head','A sturdy iron helmet.',0.1,0.05,0.2,0.5,0.1,0,0,100,0.01,'{"metal":true}',5
'Leather Cap','light','head','Light and flexible.',0.2,0.1,0.1,0.2,0.05,0,0,80,0.02,'{"leather":true}',1
```

---

### ✅ **Step 2: Update Your SQL Script to Use `COPY`**

Replace your long `INSERT` blocks in `whitefeatherdb_setup_reset_script.sql` with:

```sql
-- armor
COPY public.armor (
    item_name,
    armor_type,
    equipment_slot,
    armor_description,
    dodge_bonus,
    parry_bonus,
    block_bonus,
    armor_bonus,
    resist_bonus,
    allure_bonus,
    charisma_bonus,
    armor_durability,
    armor_degradation_rate,
    flags,
    armor_weight
)
FROM 'backend/src/main/resources/data/armor.csv'
WITH (FORMAT csv, HEADER false, DELIMITER ',', QUOTE '''');
```

> 💡 **Note**: The path should be absolute or accessible from the PostgreSQL server if running externally (see the JDBC workaround below).

---

### ✅ **Step 3: Enable CSV Import via JDBC**

The PostgreSQL `COPY FROM` command does **not** work with relative file paths from a Java application unless run **inside** the database server. Instead, for JDBC-based imports, use `COPY ... FROM STDIN` via a tool like `pgcopy`, or replace it with simpler Java-side logic to read and insert rows:

---

### ✅ **Alternative: Java-Based CSV Import**

If your database user can't access local files via `COPY`, load CSVs manually from Java using [Apache Commons CSV](https://commons.apache.org/proper/commons-csv/) or basic Java code:

```java
Path armorCsv = Paths.get("backend/src/main/resources/data/armor.csv");
try (
    BufferedReader reader = Files.newBufferedReader(armorCsv);
    Connection conn = DatabaseConnector.createConnection();
) {
    conn.setAutoCommit(false);
    String insertArmor = "INSERT INTO public.armor (item_name, armor_type, equipment_slot, armor_description, dodge_bonus, parry_bonus, block_bonus, armor_bonus, resist_bonus, allure_bonus, charisma_bonus, armor_durability, armor_degradation_rate, flags, armor_weight) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)";
    PreparedStatement ps = conn.prepareStatement(insertArmor);

    String line;
    while ((line = reader.readLine()) != null) {
        String[] values = line.split(",(?=(?:[^\\\"]*\\\"[^\\\"]*\\\")*[^\\\"]*$)", -1); // Handles commas within quotes
        for (int i = 0; i < values.length; i++) {
            String v = values[i].trim().replaceAll("^'+|'+$", ""); // Trim quotes
            ps.setObject(i + 1, v); // Let JDBC infer type or manually cast
        }
        ps.addBatch();
    }
    ps.executeBatch();
    conn.commit();
    ps.close();
}
```

### ✅ **Summary of Your New Setup**

* Store armor, weapon, etc. data in CSV files in `resources/data/`.
* Replace inline `INSERT` SQL in your `.sql` file with either:

  * `COPY` commands (if PostgreSQL server can access local file system), **or**
  * Java-based CSV reading and `PreparedStatement` execution.
* Use `DatabaseScriptRunner` as your orchestration utility.
